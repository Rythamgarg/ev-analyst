# ⚡ EV Analyst — Multi-Agent Equity Research

A production-grade CLI that turns a stock ticker into a full institutional-quality
equity research report on an EV-sector company — generated by two independent
Claude agents working in series, grounded in live market data.

```
$ npx ev-analyst --ticker RIVN --output rivn_report.html --verbose

✓ Rivian Automotive — EV Manufacturer (confidence: 0.99)
✓ Market data fetched — 4/4 sources successful
✓ Analysis complete — HOLD (conviction: MEDIUM)
✓ Verifier verdict: APPROVED (score: 84/100)
✓ Report published → rivn_report.html
```

---

## Why this exists

Most LLM "stock analysis" tools take one prompt and return one answer. That's
brittle: hallucinated numbers, missing risks, and no second pair of eyes. This
project is structured the way a real equity research desk works:

1. **A domain validator** rejects non-EV tickers before any analysis runs.
2. **A data fetcher** pulls live financials in parallel from Yahoo Finance —
   the LLM never has to guess at numbers.
3. **An analyst agent** writes a structured 8-dimensional report grounded in
   the data it was given.
4. **A separate verifier agent** — a *different* Claude instance with no
   shared context — adversarially reviews the report for overconfidence,
   missing risks, internal inconsistency, and logical fallacies.
5. **A publisher** renders to terminal + HTML and writes a JSON audit log.

The verifier can reject a report (`exit 2`) or attach a "REVIEWED WITH CAVEATS"
banner if the analyst overreached.

---

## What you get on every run

- **A formatted terminal report** with color-coded ratings across 8 dimensions
  (Valuation, Growth Quality, Balance Sheet, Moat, Management, Macro Sensitivity,
  Sentiment vs Fundamentals, Risk Matrix).
- **Bull / Base / Bear price targets** with explicit methodology.
- **A final recommendation** — `STRONG BUY` / `BUY` / `HOLD` / `SELL` / `STRONG SELL` —
  plus conviction level and one-paragraph rationale.
- **A self-contained HTML file** (if `--output` is set) with dark/light theme
  toggle and a print stylesheet.
- **A JSON audit log** (`ev_analyst_log_<TICKER>_<DATE>.json`) capturing the
  raw market data, the full analyst output, and the verifier's verdict — useful
  for backtesting, debugging prompts, or compliance review.

## Architecture

```
                   ┌───────────────────────┐
   ticker  ─────▶  │  Validator (Claude)   │  rejects non-EV → exit 1
                   └───────────┬───────────┘
                               │
                   ┌───────────▼───────────┐
                   │  Data Fetcher         │  Yahoo Finance v7/v10
                   │  (parallel, retry)    │  quote · financials · news · peers
                   └───────────┬───────────┘
                               │
                   ┌───────────▼───────────┐
                   │  Analyst Agent        │  Claude — 8-dim structured JSON
                   │  (Claude #1)          │  → recommendation + price targets
                   └───────────┬───────────┘
                               │
                   ┌───────────▼───────────┐
                   │  Verifier Agent       │  Claude — fresh context
                   │  (Claude #2)          │  → APPROVED / REVISE / REJECTED
                   └───────────┬───────────┘
                               │
                   ┌───────────▼───────────┐
                   │  Publisher            │  terminal · HTML · JSON log
                   └───────────────────────┘
```

The validator and verifier are deliberately separate API calls with no shared
conversation history, so the verifier can't be "talked into" agreement by the
analyst's framing.

## Quickstart

### 1. Install
```bash
git clone <this repo>
cd ev-analyst
./setup.sh        # installs deps, compiles TS, scaffolds .env
```

Or manually:
```bash
npm install
npm run build
cp .env.example .env
```

### 2. Try it without API keys
The `--dry-run` flag uses cached fixture data (`fixtures/TSLA.json`) and mock
agent responses. The full pipeline runs end-to-end so you can see what a real
report looks like.

```bash
node dist/cli.js --ticker TSLA --dry-run
node dist/cli.js --ticker RIVN --dry-run --output rivn.html
```

### 3. Run it for real
Add your Anthropic API key to `.env`:
```
ANTHROPIC_API_KEY=sk-ant-...
```

Then:
```bash
node dist/cli.js --ticker TSLA
node dist/cli.js --ticker RIVN --output rivn_report.html
node dist/cli.js --ticker NIO --verbose     # stream both agents live
```

## CLI reference

| Flag | Required | Description |
|------|----------|-------------|
| `-t, --ticker <SYM>` | yes | Stock ticker (TSLA, RIVN, NIO, LCID, BYD, CHPT, BLNK, ALB, SQM, FREYR…) |
| `-o, --output <file>` | no | Write self-contained HTML report to this path |
| `--verbose` | no | Stream both Claude agents' reasoning live to stdout |
| `--no-verify` | no | Skip the verifier agent (development only) |
| `--dry-run` | no | Use cached fixtures — no API keys needed |

### Exit codes
| Code | Meaning |
|------|---------|
| `0` | Report published successfully |
| `1` | Ticker is not an EV-domain company, or a fatal error occurred |
| `2` | Report was REJECTED by the verifier agent (score < 50) |

## The 8 analytical dimensions

The analyst agent must produce a rating for each of these, grounded in the
fetched data:

1. **Valuation Scorecard** — `EXPENSIVE` / `FAIR` / `CHEAP`, vs peer median and 3y history
2. **Growth Quality** — `ACCELERATING` / `STABLE` / `DECELERATING`, with unit-economics check
3. **Balance Sheet Health** — `FORTRESS` / `STABLE` / `WATCH` / `DISTRESSED`, cash runway + debt maturity
4. **Competitive Moat** — `WIDE` / `NARROW` / `NONE`, tech + brand + supply chain
5. **Management Execution** — `STRONG` / `ADEQUATE` / `WEAK`, guidance track record + capital allocation
6. **Macro & Policy Sensitivity** — `FAVORABLE` / `NEUTRAL` / `UNFAVORABLE`, IRA/China/rates
7. **Sentiment vs Fundamentals** — `CONTRARIAN BUY` / `ALIGNED` / `MOMENTUM TRAP`
8. **Risk Rating** — `LOW` / `MEDIUM` / `HIGH` / `SPECULATIVE`, with top 5 bull + bear scenarios

---

## What the verifier checks

The verifier agent runs an adversarial review with this rubric:

- **Internal consistency** — does the recommendation actually follow from the dimensional scores?
- **Data accuracy flags** — are any cited metrics implausibly extreme or contradictory?
- **Overconfidence** — are certainty claims justified given the data gaps?
- **Missing risks** — were obvious sector risks (China competition, supply chain, rate sensitivity, key-person) omitted?
- **Compliance tone** — does any language constitute unlicensed investment advice?
- **Logical fallacies** — recency bias, correlation/causation errors, anchoring, confirmation bias

Verdicts:

| Verdict | Score | Action |
|---------|-------|--------|
| `APPROVED` | ≥ 75 | Publish as-is |
| `REVISE` | 50–74 | Publish with a "REVIEWED WITH CAVEATS" banner |
| `REJECTED` | < 50 | Do not publish — exit with code 2 |

## Project layout

```
src/
  cli.ts          ← entry point + argument parsing
  types.ts        ← all shared TypeScript interfaces
  utils.ts        ← retry/backoff, spinners, formatters
  validator.ts    ← EV-domain classifier agent (Claude)
  fetcher.ts      ← parallel data fetch (Yahoo Finance v7/v10)
  analyst.ts      ← analyst agent (Claude #1) + 8-dimension prompt
  verifier.ts     ← verifier agent (Claude #2) — fresh context
  report.ts       ← terminal (chalk) + HTML (embedded CSS) renderers
  publisher.ts    ← HTML file write + JSON audit log + summary footer
fixtures/
  TSLA.json       ← snapshot data for --dry-run testing
setup.sh          ← installs deps, builds TS, sets up .env
```

---

## Tech stack

- **Runtime:** Node.js 18+ (TypeScript, compiled to ESM)
- **LLM:** Anthropic Claude (`@anthropic-ai/sdk`) — Sonnet model, streaming supported
- **Market data:** Yahoo Finance v7/v10 unofficial API via `axios`
- **CLI:** `commander` + `ora` (spinners) + `chalk` (colored output)
- **Config:** `dotenv` for API keys
